③ 事件总线
NeoForge.EVENT_BUS.post(new BoxOpenedEvent(player, boxId, giveItem, grade, bulk))
BoxOpenedEvent 特性
• post-open 通知，不可取消（物品已发放）
• 监听器可：广播稀有掉落 / 自定义统计 / 按 grade 发奖励 / 日志分析
• KubeJS 兼容：NeoForgeEvents.onEvent(...) 免依赖接入
• setResult() 仅改事件引用，不改背包
OpenedBoxTrigger 特性
• ID：csgobox:opened_box
• count 字段可选：缺省/0 无条件触发，正整数需 stat 达标
• 驱动「首开」「购物狂」等进度成就
• 与 BoxOpenedEvent 解耦，各自独立监听

5权威性与安全约束（贯穿全部开箱路径）
服务端权威：开箱结果（中奖 / grade）与磨损值（wear）完全由服务端 RNG（SecureRandom）决定。客户端 requestId 仅用于把动画结果匹配回对应请求，不参与任何授权判定。
  • 防作弊上限：CONFIG.bulkOpenCount() 为服务端强制上限（0 = 无限）；客户端确认屏的估算虽被 clamp，但服务器最终以实际库存与上限为准，构造包无法多开。
  • 开箱冷却：OPEN_BLOCKED_UNTIL_TICK（10 tick）防止同 tick 重复开；tickOpenBlockMap 由服务器 tick 循环定期清理过期项，避免 Map 无限增长。
  • 批量原子性：验证 / 快照 / 异步计算先发生，消耗（box + key）延迟到主线程 finalizeBulkOpen；提交到消耗间抛异常 → 玩家零损失。密钥不足时仅回退箱子，绝不多扣。
  • 库存一致性：尝试消耗时跳过 ItemCsgoBox 实例（避免把箱子误当钥匙扣减）；26.x 额外覆盖 armor / offhand 槽位，弥补旧实现仅扫主背包导致的漏扣。
  • 等级池缓存：GradeMapCache 按 boxId 缓存等级池，BoxRegistry reload 时失效，确保配置变更后不会服务过期奖池。

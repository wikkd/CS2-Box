# 对接网页开发师文档 · CS2-Box 知识库前端（wiki-site）

这份文档写给接下来要维护或扩展 `wiki/wiki-site/` 的前端同事。它假设你熟悉 React，但没碰过这个仓库。读完你应该能本地跑起来、知道数据从哪来、改东西要碰哪些文件，以及踩过哪些坑。

---

## 1. 这个站点到底是什么

`wiki/wiki-site/` 是一个**零后端、可离线打开**的知识库网站，用来呈现 `wiki/wiki/` 下那套 Markdown 知识库（目前约 79 页，分 sources / concepts / entities / comparisons 四类）。

它最特别的一点：生产构建产物是**单个 `dist/index.html`**，所有 JS/CSS/资源都被 `vite-plugin-singlefile` 内联进去，双击就能用 `file://` 打开，不需要任何服务器。这对「把知识库发给别人、或者塞进 mod 发行包」很友好。

---

## 2. 技术栈

| 层 | 选型 |
|---|---|
| 构建 | Vite 5（`vite.config.ts` 里 `base: './'` + `vite-plugin-singlefile`） |
| 框架 | React 18 + TypeScript |
| 路由 | react-router-dom 6，**HashRouter**（`#/page/xxx`，不是 History 路由） |
| 样式 | Tailwind CSS v4（`@tailwindcss/vite` 插件，`@theme` 自定义 token） |
| Markdown 渲染 | react-markdown 9 + remark-gfm + rehype-slug + rehype-highlight |
| 图标 | lucide-react |
| 图表 | 手写 SVG 组件（`AreaChart` / `SizeChart` / `GitTimeline`），**没有引图表库** |

依赖都在 `package.json`，没有运行时后端调用，所有数据在构建期从本地文件 / git 历史生成。

## 3. 目录结构与职责

```
wiki-site/
├── index.html
├── package.json
├── vite.config.ts          # base './' + singlefile，决定 file:// 直开
├── serve.cjs               # 零依赖静态服务器（绑 0.0.0.0，局域网可访问）
├── scripts/
│   ├── build-wiki-data.mjs # wiki/*.md → src/data/wiki.json
│   └── gen-dashboard-data.mjs # git 历史/体积/更新日志 → 三个 json
└── src/
    ├── main.tsx            # 入口，挂 HashRouter
    ├── App.tsx             # 路由表 + Layout + DocPage
    ├── data.ts             # wiki.json 的读取接口（getPage/getCategories/...）
    ├── types.ts            # 全部 TS 类型
    ├── index.css           # Tailwind 导入 + 主题 token + Markdown 样式
    ├── useTheme.ts         # 明暗主题（默认暗色）
    ├── components/
    │   ├── Sidebar.tsx     # 左侧分类导航 + 搜索 + 主题切换
    │   ├── MarkdownDoc.tsx # ReactMarkdown 封装（复制按钮、外链新窗口）
    │   └── dashboard/      # 开发数据面板（Overview/SizeChart/GitTimeline/...）
    └── data/
        ├── wiki.json       # 构建生成，别手改
        ├── git-history.json
        ├── size-history.json
        └── dev-log.json
```

`src/data/*.json` 全是构建产物，**不要手动编辑**，重新跑构建脚本会覆盖。

## 4. 数据从哪来（两条管线）

### 4.1 知识内容管线：`build-wiki-data.mjs`

输入：`wiki/wiki/**/*.md`（相对 `wiki-site` 往上两级）。
逻辑：
1. 递归收集所有 `.md`；按顶层目录映射到分类（`sources`/`concepts`/`entities`/`comparisons`，其余归 `meta`）。
2. 自己写了个极简 frontmatter 解析器（不引外部依赖），读 `title` / `type`；
3. 把 `[[wikilink|标签]]` 重写成 `[标签](wikilink:slug)`——注意 scheme 是 `wikilink:`，前端靠它识别站内跳转；代码块和行内代码会被临时抽离再还原，不会被误改；
4. 去掉正文开头的 H1（标题由 UI 渲染）；
5. 额外生成 `plain` 纯文本字段，给客户端搜索用。

输出 `src/data/wiki.json`：
```jsonc
{
  "generatedAt": "ISO 时间",
  "total": 79,
  "categories": [ { "id", "label", "icon", "pages": [slug...] } ],
  "pages": { "<slug>": { slug, category, type, title, frontmatter, markdown, plain } }
}
```

`data.ts` 就是围绕这个结构做的读取封装（`getPage` / `getCategories` / `orderedSlugs` 等）。

### 4.2 开发指标管线：`gen-dashboard-data.mjs`

从 git 仓库现挖，产出三个 JSON（无后端）：
- `git-history.json`：提交列表 + 贡献者（`git log --numstat`）；
- `size-history.json`：各模块 blob 体积随时间变化（`git ls-tree -r -l <ref>`，取 tag + 补足到约 14 个采样点，`MODULES = common/v1_21_1/v26_1_2/v26_2`）；
- `dev-log.json`：从 `CHANGELOG.md` 解析最近几个版本的变更条目 + 最近提交。

`/dashboard` 路由把这些画成 SVG 图表。

## 5. 本地运行与构建

```bash
cd wiki/wiki-site
npm install                 # 装依赖（Vite/React/Tailwind 等）

npm run dev                # = build:wiki + build:metrics + vite
                           #   先生成数据 json，再起 dev server（5173）
npm run build              # = build:wiki + build:metrics + vite build
                           #   产出 dist/index.html（单文件）
npm run preview            # vite preview，4173 端口
node serve.cjs [port]      # 零依赖静态服务，默认 8080，绑 0.0.0.0
```

`dev` / `build` 都会先跑两条数据管线再启动 Vite——改了 `wiki/*.md` 或 `CHANGELOG.md` 后必须重跑，否则页面还是旧数据。

`dist/index.html` 可以直接双击用浏览器打开（`file://`），也可以丢到任何静态托管。`serve.cjs` 适合局域网共享，带 SPA 兜底（未知路径回 index.html）和目录穿越防护。

## 6. 约定与踩过的坑

这些是从仓库历史里总结的，改之前先读一遍：

- **`vite build` 不跑 `tsc`。** 未定义的变量、类型错误不会在构建期炸出来，只会漏到 CI 甚至漏到运行时。提交前本地至少 `npx tsc --noEmit` 扫一遍（或接入 CI 类型检查）。
- **黑屏基本都是单组件运行时崩溃。** 因为 singlefile 把所有东西塞进一个 HTML，一个组件抛错就可能整页白/黑。定位办法：用 Playwright headless 加载 `dist/index.html`，抓 `pageerror` 事件，看是哪个组件在 mount 时炸了。
- **HashRouter，不是 History 路由。** 所有路由走 `#`，所以静态服务器只要兜底到 `index.html` 就行，不需要服务器端 rewrite 规则。新加页面记得走 `/page/:slug` 这套。
- **主题默认暗色。** `useTheme` 里 localStorage 没有值时回退到 `true`（暗色）。`index.css` 用 class-based 暗色（`<html class="dark">`），通过 `@custom-variant dark` + `@theme` 把 CSS 变量映射成 Tailwind 工具类（`bg-bg` / `text-text` / `border-border` …）。
- **`wikilink:` scheme 是站内跳转的约定。** Markdown 里的 `[[xxx]]` 被换成 `wikilink:slug`，`MarkdownDoc.tsx` 的 `A` 组件目前只处理了外链（`http(s)`），站内 wikilink 的点击跳转需要你自己接（或后续扩展）。
- **不引图表库。** dashboard 的图都是手写的 SVG 组件，加新图照着 `AreaChart.tsx` / `SizeChart.tsx` 写，别顺手装 echarts/recharts。
- **frontmatter 解析很轻量。** `build-wiki-data.mjs` 自己抠 YAML，只认 `key: value` 和简单数组，**不支持嵌套对象或多行值**。wiki 页面写复杂 frontmatter 会被静默忽略或解析错。

## 7. 常见扩展怎么做

**加一篇知识库页面**
在 `wiki/wiki/<分类>/` 下新建 `.md`，frontmatter 至少给 `title`；重跑 `npm run build:wiki`（或 `npm run dev`）。分类不在 `sources/concepts/entities/comparisons` 里的会归到 `meta`。

**加一个新分类**
改三处：`build-wiki-data.mjs` 的 `CATEGORY_META`（加 id/label/icon/order）、`src/types.ts` 的 `CategoryId` 联合类型、`index.css` 里按需配色。

**加一个 dashboard 指标**
在 `gen-dashboard-data.mjs` 里产出新 JSON → `types.ts` 加类型 → 在 `components/dashboard/` 下写（或改）一个 SVG 组件，并在 `Dashboard.tsx` 里挂上。注意 `MODULES` 常量只列了四个模块，算体积时新增模块要补。

**改主题配色**
只动 `index.css` 的 `:root` 和 `.dark` 下的 CSS 变量（`--bg`/`--text`/`--accent`…），`@theme` 映射会自动同步成 Tailwind 工具类，不用去改组件。

**想让页面渲染 Mermaid 流程图**
当前 `MarkdownDoc.tsx` 没有接入 mermaid。要支持，要么加 `rehype` 插件在构建期转成 SVG，要么在组件里用 `mermaid` 运行时渲染。这是个合理的扩展点，但记得 singlefile 构建下运行时渲染需要把 mermaid 运行时一并内联。

## 8. 与整体技术栈的衔接

wiki-site 是 CS2-Box 「知识资产」这一支的呈现端。上游是 `wiki/wiki/` 的 Markdown 源（由维护者手写、`wiki_lint.py` 做一致性检查），再往上是 `cloud_ingest.py` 把同样的内容推到 WorkBuddy 云端资料库做团队检索。wiki-site 只消费本地 Markdown，不参与云端摄取——这两条链路目前是平行的，前端不需要关心云端那套。

更宏观的技术栈全景（构建、镜像纪律、服务端权威开箱、CI 等）见同目录的《CS2-Box 技术栈全景分析》，以及 `docs/diagrams/` 下已有的架构图与开箱流程图。
